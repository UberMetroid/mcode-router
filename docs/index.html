The OODA Pipeline

observe → orient → decide → act

OODA is Observe → Orient → Decide → Act. Decide is the orchestrator's own phase — it locks the files in scope, the execution mode and the build/test gate, so it never spends a worker lane. The router exposes the worker-facing work as four stage pins: observe, orient, act and verify, where verify is the off-family review OODA keeps inside Act, promoted to a stage of its own so it can be pinned, cached and rotated on its own.

Every stage is a separate, quota-aware call with its own lane, model and effort resolution. The orchestrator stays thin: it owns the plan and the final call while the workers do the reading, the writing and the grading. Each card below is one phase, in order.

Observe

ooda_recon — Read-Only Recon

Answers questions about repository structure, build and test commands, and the location of a symbol. It never writes, creates or deletes a file, and it never runs a build.

Orient

ooda_orient — Root Cause & Plan

Synthesizes root cause, invariants, blast radius and file coupling for a problem, then proposes an ordered plan. Also strictly read-only.

Decide

Orchestrator — Scope, Mode & Gate

No worker lane and no model call: the orchestrator locks the files in scope, the execution mode (sequential or parallel worktrees) and the build/test gate before a single edit is made. It keeps the plan and the final call, which is how the orchestrator stays thin.

Act

ooda_task — Scoped Implementation

Executes a scoped coding task in the working directory or in an isolated git worktree gated by atomic flock leases, so parallel builds never collide. Act is gated by ooda_review: the off-family diff review that OODA keeps inside Act, promoted to a stage of its own so it can be pinned, cached and rotated independently.

Static Go Core & MiniMax Code Adapter

cmd/mcode-router • internal/* • bin/mcode-router-mcp

One zero-dependency Go engine serves every role: the CLI dispatcher, the MCP server and the fleet scheduler all live in the same static binary, so no extra runtime or dependency is introduced into your host.

Multi-Call Binary

One Static Executable, Two Entry Points

Built with CGO_ENABLED=0 and zero third-party packages. It inspects argv[0] to run as mcode-router (CLI dispatcher and fleet admin) or mcode-router-mcp (MCP server over stdio), with instant startup and no shell bridge.

Shared Engine

One Quota Store, One Verifier

Core packages live under internal/{fleet,envelope,dispatch,verify,worktree,cli,install,theme} and share a single quota store, lease mechanism, worktree allocator and diff verifier instead of duplicating them per host.

Fail-Closed Supply

Zero-Go Verified Releases

GitHub Releases publish cross-compiled static binaries (linux/darwin, amd64/arm64) alongside SHA256SUMS. Hosts without Go verify the checksum fail-closed before installing.

House-Law Gate

make all Before Every Landing

The gate ladder enforces portability, file shape, directory density and identifier limits, then runs go vet, go test -race and binary dogfood checks with zero skips. No author home paths, no embedded credentials, no sh -c.

First Principles & Zero-Trust Architecture

Zero Trust • Quota Economics • Worktree Isolation

Built directly from first principles: fixed-clock subscriptions lose all unused quota when their window resets, and under Zero Trust no model family should ever grade its own output or touch paid credits unattended.

Fast Path

Thin Orchestrator (<10% Burn)

Top-level chat owns planning and Decide while workers handle recon, orientation and scoped edits, keeping the orchestrator's own quota protected.

Zero Trust

Cross-Model Verify & Rotation

The verify stage excludes every model family that wrote or attempted the diff and rotates families on rejection or mismatch. Hard cap of 3 act loops.

Identity

Pinned Models Survive a Failover

When a pinned stage falls over to another lane, a model whose family matches the fallback lane is kept and a foreign one is scrubbed. A stage never silently changes models because its lane cooled down, and a model whose reasoning is a variant is dispatched without an effort it cannot take.

Isolation

Isolated Worktree Swarms

Multi-module manifests spin up one isolated git worktree per task on branch ooda/<id> gated by atomic flock concurrency leases.

EXPIRING

Use Before Reset

Prioritizes soonest-resetting windows and 0.5x UTC off-peak tariffs so capacity never goes to waste.

READY

Healthy Pools

Rotates evenly across healthy bounded pools (muse, grok, mistral).

SPARING

Save Last Cap

When only one bounded lane remains active, free SWE-2 and mcode pools handle routine tasks first.

CREDITS

Opt-In Only

Blocks paid devin-fusion credits from automatic selection, saved pins and reviews unless explicitly requested.

COOLING

Auto-Wake

Parses ISO and relative resets, caps transient 429 backoffs, and auto-wakes lanes when timers expire.

Lane Priority by Stage

Each stage has its own lane order; the chains below are lane priorities, not the phase order. The phases run observe → orient → decide → act, and verify gates act.
observe (recon): devin-fast → mcode → devin-pro → muse
act (quota-driven): Expiring clocks → 0.5x off-peak → short windows → free lanes
parallel stripe: muse → grok → mistral → devin-pro → devin-fast → mcode
fallback chain: muse → grok → mistral → devin-fast → devin-pro → mcode
verify (review): mcode → devin-fast → devin-pro → grok → mistral → muse

Hard Binary Guardrails

Workers run with MCODE_ROUTER_DEPTH=1 & ROUTER_DEPTH=1 (or higher). The Go CLI blocks recursive dispatch, --probe, --cleanup, and quota mutations with exit 2 whenever depth >=1, and hard-rejects gemini* or orchestrator* models on any worker or review lane.

Unconfigured Agents

Other Agent CLIs (Not Wired — No Active Paid Subscription)

mcode-router does not currently wire Anthropic Claude Code (claude), OpenAI Codex CLI (codex), Cursor CLI (cursor-agent), GitHub Copilot CLI (copilot), Sourcegraph Amp (amp), or Factory Droid (droid) because we don't pay for subscriptions to them today. New CLI adapters can be added modularly under internal/dispatch/ and internal/fleet/ if you want to route your own plan.

The MCP Server

bin/mcode-router-mcp • stdio

mcode-router ships a Model Context Protocol server inside the same static binary. MiniMax Code launches it over stdio, and the model calls the OODA stages directly — no shell round-trip, no plugin bridge, no extra process to babysit. Each tool maps to the matching CLI verb, so lane, model, effort, complexity and timeout overrides all apply.

Tool Stage What It Does
ooda_recon observe Read-only reconnaissance of repository structure, build and test commands, and symbol locations.
ooda_orient orient Root cause, invariants, blast radius and file coupling, then an ordered implementation plan.
ooda_task act Executes a scoped coding task in the working directory or in an isolated worktree.
ooda_review verify Independent cross-model review of the working-tree diff; the reviewer is never the authoring family.
ooda_status fleet Live fleet state: lane status, tier, model, effort, quota resets and the stage routing matrix.
ooda_usage fleet Per-lane quota windows (5h/24h/7d/30d), UTC tariffs and current spend.
ooda_live fleet Live worker telemetry: the lane, model, effort, phase and tokens-per-second of every dispatch running right now, plus the last completed run.
ooda_set_stage fleet Pin or reset a stage lane (observe/orient/act/verify) globally or for one repo.
Context Hooks

Automatic Routing, Zero User Input

The SessionStart and UserPromptSubmit context hooks inject live fleet status and the stage routing matrix into every session. Lane, model and effort selection is therefore automatic: no probe call, no model round-trip, no picker to operate.

Override Knobs

Same Verbs as the CLI

Every stage tool accepts the same overrides as its CLI counterpart: a forced lane, a forced model, an effort level, a capability complexity, a profile, worker skills, scoped files and a timeout.

Host Package

Skills, Profiles & Server Entry

The installer registers the mcode-router MCP server entry plus the mcode-router, lane and harden skills and eight OODA agent profiles, validated against the host manifest and packaging rules.

Cross-Model Diff Verification

mcode-router --review .

No model family grades its own patch. mcode-router --review excludes the authoring family automatically, tracks pre-task HeadRef state so worker commits never evade scope or review checks, renders untracked files as synthetic hunks, and fails closed on any [P0-3], UNKNOWN, or SKIPPED result.

≤ 8 KiB Working Tree

Native Repo Review

Invokes mcode exec review with --permission smart --max-steps 15 so the reviewer inspects surrounding context directly in the workspace.

> 8 KiB or Committed

Bounded Patch Audit

Streams a bounded patch audit prompt with --permission smart --prompt-mode coding --max-steps 25 against baseRef..working-tree or unborn HEAD.

Fail-Closed Backup

Off-Family Fallback

On cooldown, timeout (240s default), or UNKNOWN verdict, verification rotates across mcode → devin-fast → devin-pro → grok → mistral → muse.

Install

What the Installer Wires

The web installer clones or fast-forwards UberMetroid/mcode-router into ${XDG_DATA_HOME:-~/.local/share}/mcode-router and invokes ./install.sh. On hosts without Go 1.22+, install.sh downloads the matching static GitHub Release binary and verifies its SHA-256 checksum against SHA256SUMS before installing. It links ~/.local/bin/mcode-router and bin/mcode-router-mcp, then wires the MiniMax Code adapter: skills, agent profiles, the mcode-router MCP server entry and the SessionStart / UserPromptSubmit context hooks.

Uninstall

Clean, Guarded Removal

./install.sh --uninstall removes only symlinks resolving into this repo and leaves every other MiniMax Code server and hook in place. Quota state and backups stay intact unless you pass --purge, and the web installer refuses to purge a dirty or unpushed git checkout.

State Paths & House-Law Gates

Quota state (v9) and global stage pins persist under ${XDG_STATE_HOME:-~/.local/state}/mcode-router/quota.json (override via MCODE_ROUTER_QUOTA_FILE); --local per-repo pins live out-of-git in workspaces/<id>.json. Runtime state is never mutated inside git.
